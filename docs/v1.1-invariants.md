# ATMAN-LATTICE v1.1 — Additional Invariants

## I-59 — Full Runtime Mediation

Privileged lifecycle operations count as governed only when executed through the runtime boundary:

```text
observe / issue / consume / revoke / merge
    -> runtime authority gate
    -> privileged primitive
```

A client-side proof or local helper result is not itself privileged execution.

## I-60 — Server-Owned Capability Secret

A use token or authorization event is valid only when authenticated by a key held by the runtime deployment.

```text
client-selected key_id != client-selected signing secret
```

Request fields cannot replace the server key map.

## I-61 — Consume Requires Authority

Possession of a valid `UseToken` does not itself grant permission to consume it.

```text
ValidToken ∧ CurrentContext
    does not imply
AuthorizedConsumption
```

Consumption additionally requires an exact `USE_TOKEN_CONSUMER` authority proof for the runtime-reconstructed consume action.

## I-62 — Atomic Terminal Authorization State

For each exact token digest, at most one terminal event may commit:

```text
count({CONSUMED, REVOKED} for token_digest) <= 1
```

The reference runtime enforces this across separate processes with a server-owned SQLite transaction using `BEGIN IMMEDIATE`.

## I-63 — Stale Generation Cannot Commit

If a caller signs or submits against authorization ledger generation `N`, and the server state has advanced to `N+1`, the stale operation must not append another event.

```text
expected_generation != current_server_generation
    -> no commit
```

The exact rejection may occur at action-digest verification, generation comparison, or terminal-token validation.

## I-64 — Client Ledger Is Not Authority

The client cannot define current authorization history by supplying its own ledger snapshot.

```text
CurrentAuthorizationState = RuntimeStore(identity_ref)
```

not:

```text
CurrentAuthorizationState = request.ledger
```

## I-65 — Runtime-Mediated Reconciliation

A valid merge result must be created only after the runtime validates exact ancestry, both branch histories, restore proofs, resolution completeness, target lineage parameters, and merge authority.

```text
ValidParents != RuntimeAuthorizedMerge
```

## I-66 — Lifecycle Closure

The governed trust chain is closed only when observation, capability issuance, terminal authorization state, and reconciliation all use the same runtime trust boundary and current authority policy.

```text
Observe
  -> Authorize
  -> Issue
  -> Consume/Revoke
  -> Reconcile
```

No stage may treat a previous stage's artifact as permission to bypass its own use-time authority check.
