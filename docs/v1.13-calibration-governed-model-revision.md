# ATMAN-LATTICE v1.13 — Calibration-Governed Model Revision

v1.13 turns calibration diagnostics into a governed model-revision path without allowing the observer to silently rewrite its own history.

## Core law

```text
LearningFromError != ErasingError
```

A historical miscalibration signal may justify a revision proposal. It does not itself authorize mutation.

```text
CalibrationSignal
      |
      v
ModelRevisionProposal
      |
      v
CounterfactualReplay
      |
      v
IndependentReview
      |
      v
ApplyNewGeneration
```

Each arrow is a separate receipt and a separate authority boundary.

## Protocol plane

```text
ATMAN-REVISION/1.13
```

Worker:

```bash
python -m model.revision_worker
```

Operations:

```text
register_revision_proposal
record_counterfactual_replay
record_revision_review
apply_model_revision
get_revision_state
```

## Proposal requires a calibration signal

`register_revision_proposal` reconstructs the current calibration-family snapshot from persisted v1.12 observations under explicit sample/threshold policy.

A proposal is accepted only when the snapshot status is:

```text
MISCALIBRATION_SIGNAL
```

It binds:

- exact current distribution hash;
- exact current likelihood-model hash;
- calibration snapshot hash;
- proposed likelihood vector;
- existing conditioning parent set;
- exactly the next model generation;
- proposer identity and reason.

```text
CalibrationSignal != RewriteAuthority
Proposal != Mutation
```

## Counterfactual replay

Replay evaluates the proposed likelihood vector on the same historical resolved observations used by the model family.

For every scored historical case it preserves:

```text
historical calibration hash
resolved hypothesis
observed POSITIVE / NEGATIVE
old predicted probability
proposed predicted probability
old Brier score
proposed Brier score
```

The replay receipt binds the complete sorted set of case hashes.

Possible statuses:

```text
INSUFFICIENT_SCORABLE_CASES
IMPROVED
NO_IMPROVEMENT
```

`IMPROVED` requires the proposed mean Brier score to be strictly lower than the old mean Brier score.

```text
ReplayImprovement != Approval
```

Replay proves only how this proposal performs against the bound historical sample set. It does not prove future performance or causal correctness.

## Independent review

A proposal cannot review itself.

```text
proposer_ref != reviewer_ref
```

An `APPROVE` review is valid only when the bound replay status is `IMPROVED`.

Review outcomes:

```text
APPROVE
HOLD
REJECT
```

```text
Replay != Review
Review != Apply
```

## Apply is use-time bound

Before mutation the runtime verifies:

1. the current model still equals the proposal's base model;
2. the current distribution still equals the proposal's base distribution;
3. the persisted replay and review bind the exact proposal;
4. review is `APPROVE`;
5. replay is `IMPROVED`;
6. replay is recalculated against all currently persisted calibration observations.

If the calibration history changed after replay/review, apply rejects:

```text
OldReplay != CurrentRevisionAuthority
```

A new proposal/replay/review cycle is required.

## Revision never rewrites old evidence

Successful apply creates a new `MultiLikelihoodModel` generation:

```text
Model N -> Model N+1
```

The runtime updates the current-model pointer but also appends `model_revision_history` containing:

```text
old model JSON
new model JSON
proposal hash
replay hash
review hash
revision receipt
```

All v1.12 calibration targets, resolutions, and historical calibration receipts remain unchanged.

```text
NewModel != RewrittenOldModel
LearningFromError != ErrorErasure
```

## Authority separation

v1.13 introduces:

```text
MODEL_REVISION_PROPOSER
MODEL_REVISION_REPLAY_KEEPER
MODEL_REVISION_REVIEWER
MODEL_REVISION_APPLIER
```

These authorities are not interchangeable.

```text
Diagnose != Propose != Replay != Review != Apply
```

The runtime additionally requires the reviewer identity to differ from the proposer identity.

## Scope boundary

v1.13 revises the **likelihood values** of a current multi-hypothesis model while preserving its hypothesis set and conditioning-parent set.

It deliberately does not yet auto-rewrite dependency declarations from `INDEPENDENCE_CHALLENGED`. Dependency revision needs a separate structural proposal because changing `INDEPENDENT` to `CONDITIONAL` changes what evidence context a likelihood means, not merely a numeric parameter.

```text
DependencyChallenge != PermissionToInventConditioningContext
```

That is a candidate for a later structural-revision layer.

## Reference-boundary caveats

The current runtime remains a SQLite/process reference boundary, not consensus and not a hostile-host sandbox. Counterfactual replay evaluates historical fit, not out-of-distribution robustness. Production use needs held-out evaluation, rollback-resistant storage, protected resolution provenance, calibration-drift monitoring, and governance appropriate to model risk.
