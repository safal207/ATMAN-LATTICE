# ATMAN-LATTICE v1.16 — Multiple-Comparison / Search-Budget Invariants

v1.16 governs repeated access to the v1.15 held-out structural evaluation surface. It is a finite-search and multiplicity-control layer, not a p-value engine and not a causal-identification protocol.

## I-287 — Finite Held-Out Search Budget

A search family has a finite number of unique candidate evaluations.

`OneHeldOutSet != InfiniteSelectionBudget`

## I-288 — Reservation Precedes Exposure

A candidate must consume a search reservation before its held-out partition is evaluated.

`Reserve(candidate) -> Evaluate(candidate)`

not the reverse.

## I-289 — One Candidate, One Exposure Unit

Within one search family, one exact `candidate_hash` can own at most one reservation.

## I-290 — Repeated Evaluation Is Not Fresh Evidence

Re-requesting an already reserved candidate returns the same reservation and does not advance the search ordinal.

`RepeatedEvaluation != FreshEvidence`

## I-291 — Search Budget Survives History Change

The search family is bound to subject + pair + structural policy + search policy, not to one history hash or base graph generation.

New history does not reset prior held-out exposure count.

## I-292 — Multiplicity Threshold Is Monotonic

For ordinal `n`:

`threshold_n = base_threshold + multiplicity_penalty * (n - 1)`

With non-negative penalty, later unique looks cannot receive a lower multiplicity threshold.

## I-293 — Underlying Held-Out Validation Remains Separate

The v1.15 held-out receipt is preserved independently from the v1.16 search-adjusted receipt.

`HeldOutValidation != SearchAdjustedValidation`

## I-294 — Held-Out PASS Is Not Search-Corrected PASS

A `HELDOUT_IMPROVED` v1.15 result may still become `MULTIPLICITY_REJECTED` under v1.16.

## I-295 — Budget Exhaustion Is Not Invalidity

No remaining search budget means another held-out look is forbidden under the policy. It does not imply the unevaluated candidate is false or invalid.

`BudgetExhausted != CandidateInvalid`

## I-296 — Unbudgeted Exposure Is Not Admissible

A candidate already evaluated through the legacy/unbudgeted v1.15 runtime cannot later be presented as a fresh v1.16 search-budget observation.

## I-297 — Evaluator Is Independent From Proposer

The actor proposing a structural candidate cannot evaluate its held-out result in v1.16.

## I-298 — Evaluator Is Independent From Budget Keeper

The actor allocating the held-out search slot cannot also evaluate that slot.

## I-299 — Current Reserved Set Must Be Complete Before Selection

Every reservation in the current structural context must have a recorded search-adjusted evaluation before selection can finalize.

## I-300 — Selection Binds the Full Family Exposure State

A search selection records all cumulative family reservation hashes, including reservations from older history/base contexts.

## I-301 — New Exposure Stales Old Selection

A new reservation after selection changes the family exposure set and invalidates the old selection at apply time.

`OldExposureSet != CurrentSelectionAuthority`

## I-302 — History Change Stales the Current Context

The selected candidate and current candidate set must still bind the current dependency history at apply time.

## I-303 — Base Graph Change Stales the Current Context

A selection for Graph N cannot mutate Graph N+1.

## I-304 — Search Policy Is Explicit and Immutable in the Reference Runtime

Search capacity and multiplicity thresholds are server-persisted policy, not caller-supplied use-time truth.

## I-305 — Search Selection Is Not Mutation

`SELECTED != APPLIED`

A selected search-corrected candidate still requires independent review and apply authority.

## I-306 — Search Review Is Independent

The search reviewer cannot be the selector or the selected candidate proposer.

## I-307 — Search Correction Is Not Causality Proof

Passing finite-search governance strengthens predictive model-selection discipline only.

`SearchCorrectedImprovement != CausalityProof`

## I-308 — Search Multiplicity Is Not Knowledge

Trying more graph hypotheses does not itself create evidence.

`SearchMultiplicity != Knowledge`

## I-309 — Exposure History Is Preserved

Reservations, underlying held-out validation, search-adjusted evaluation, selection, review, and old/new graph state are retained in revision history.

## I-310 — Search-Budget Evidence Is Not Execution Authority

Search reservations, corrected evaluations, and selections authorize no privileged execution outside their explicit structural-revision role.
