# ATMAN-LATTICE v0.9 — Authority Enforcement Invariants

These invariants extend the v0.8 authority model from proof verification into the governed execution path.

## I-46 — Gate Before Execution

> A privileged primitive must not execute before its authority proof has passed all current enforcement checks.

For privileged operation `O` and gate `G`:

```text
G(O, proof, policy) = PASS -> O may execute
G(O, proof, policy) = FAIL -> O must not execute
```

Post-hoc audit is not equivalent to pre-execution enforcement.

## I-47 — Operation-Exact Role Binding

> A role being present in a grant does not authorize every operation covered by that grant.

Each governed operation has one required role in v0.9:

```text
A1 -> A1_OBSERVER
A2 -> A2_OBSERVER
A3 -> A3_BINDER
A4 -> A4_KEEPER
issue token -> USE_TOKEN_ISSUER
revoke token -> USE_TOKEN_REVOKER
merge -> BRANCH_MERGER
```

Therefore:

```text
proof.role in grant.roles
```

is necessary but not sufficient. We also require:

```text
proof.role == required_role(operation)
```

## I-48 — Operation-Exact Scope Binding

> A scope being present in a grant does not authorize a proof to choose a different granted scope for the current operation.

The proof must bind to the exact scope reconstructed from the runtime subject:

```text
observer / merge: identity:<identity_ref>
authorization lifecycle: authorization:<identity_ref>
```

Therefore:

```text
proof.scope == required_scope(operation, runtime_subject)
```

must hold at enforcement time.

## I-49 — Runtime Action Reconstruction

> Authority is checked against the action reconstructed from the actual runtime inputs, not against a caller-supplied description of what it claims it will do.

For runtime inputs `x`:

```text
action_runtime = CanonicalAction(x)
```

and the proof must satisfy:

```text
proof.action_digest == H(action_runtime)
```

This prevents authorization for one operation instance from being reused for a nearby but different instance.

## I-50 — Current Policy Gate

> A historically valid proof cannot enter a privileged primitive under a different current authority-policy generation.

```text
proof.policy_generation
== grant.policy_generation
== current_policy_generation
```

must hold before execution.

## I-51 — Mechanism / Permission Separation

> The semantics of a transition and the authority to invoke that transition are separate contracts.

Low-level primitives define the transition semantics. The governed enforcement boundary defines permission to invoke them.

This preserves testability while preventing the permission model from becoming implicit inside every primitive.

## I-52 — Governed-Boundary Completeness

> Every operation designated privileged by the governed runtime must have an explicit role mapping, scope rule, canonical action commitment, and pre-execution gate.

For v0.9 the governed set is:

```text
{
  observe_space,
  observe_time,
  cross_axis_bind,
  global_coherence,
  issue_use_token,
  revoke_use_token,
  merge_branches
}
```

Adding a new privileged operation without adding those enforcement bindings is an incomplete protocol change.

## v0.9 acceptance additions

A governed invocation is provisionally admissible only when:

```text
trusted_grant_issuer = true
grant_signature = valid
grant_time_window = current
grant_policy_generation = current
proof_signature = valid
proof_subject_key = exact
proof_action_digest = exact_runtime_action
proof_role = exact_operation_role
proof_scope = exact_runtime_scope
```

Only after all checks pass may the low-level primitive execute.

## Executable counterexamples

The v0.9 test suite includes failures where:

1. a role is cryptographically valid and present in the grant but is the wrong role for the operation;
2. a scope is cryptographically valid and present in the grant but is the wrong scope for the runtime identity;
3. the policy generation changed after the proof was issued;
4. A1/A2/A3/A4 require distinct role gates;
5. token issuance requires `USE_TOKEN_ISSUER`;
6. token revocation requires `USE_TOKEN_REVOKER` and binds the exact token/ledger/action;
7. merge requires `BRANCH_MERGER` and binds the exact reconciliation inputs;
8. a failed role gate prevents the wrapped primitive from being called at all.

## Non-bypassability boundary

The pure Python research package does not claim hostile-code isolation. Direct imports of low-level primitives remain possible by design for formal testing.

The invariant proven here is:

> governed operations cannot cross `model.enforcement` without authority.

Production non-bypassability requires a stronger deployment boundary around the primitive itself.
