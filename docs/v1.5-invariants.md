# ATMAN-LATTICE v1.5 Invariants

These are engineering contracts over transition-geometry evidence. They do not assert physical torsion or curvature.

## I-96 — Geometry Enters Coherence Explicitly

A3/A4 coherence decisions must not ignore transition-geometry evidence when such evidence is supplied.

```text
A3(base) + geometry -> A3-GEOMETRY
A4(base) + A3-GEOMETRY* -> A4-GEOMETRY
```

## I-97 — HOLD Is Distinct From FAIL

Path dependence may require reconciliation without proving that the underlying transitions are invalid.

```text
HOLD != FAIL
```

A consumer must not silently map `HOLD` to `PASS` or `FAIL`.

## I-98 — Exact Geometry Evidence Binding

A geometric gate must re-verify the exact origin, operators, ordered path endpoints, loop endpoints, and receipt hashes.

```text
SelfConsistentReceipt != ProofOfThisPath
```

## I-99 — History-Only Divergence May Remain Coherent

If two paths are semantically equivalent while cryptographic history differs, policy may preserve both histories without declaring semantic incoherence.

Default reference behavior:

```text
SEMANTICALLY_CLOSED_HISTORY_DIVERGENT -> PASS
SEMANTICALLY_CLOSED_WITH_HOLONOMY -> PASS
```

The historical difference remains evidence and is not erased.

## I-100 — Semantic Torsion Requires Explicit Policy

When order changes semantic state, global commit must be governed by an explicit geometric policy.

Default reference behavior:

```text
TORSION_DETECTED -> HOLD
```

## I-101 — Semantic Curvature Requires Explicit Policy

When a loop fails to return to the same semantic point, the result must not be treated as a flat loop.

Default reference behavior:

```text
CURVATURE_DETECTED -> HOLD
```

## I-102 — Geometric Policy Binding

Every geometric decision must bind to the exact policy hash used to classify evidence.

A4 must reject an A3 geometry receipt evaluated under another policy unless an explicit policy-translation mechanism exists.

## I-103 — Geometric Identity Binding

A4 must not compose geometric observer receipts belonging to another identity into its coherence result.

```text
identity(A4) != identity(geometry) -> FAIL
```

## I-104 — Decision Severity Is Monotonic

For aggregation:

```text
PASS < HOLD < FAIL
```

A more severe geometric result cannot be downgraded by another locally successful receipt.

## I-105 — Geometry Evidence Is Not Execution Authority

A torsion, curvature, A3-GEOMETRY, or A4-GEOMETRY receipt describes coherence evidence. It does not grant the right to execute, prune, merge, overwrite, or reconcile histories.

Execution still requires the appropriate authority/capability/runtime checks.

## Reference default

```text
CLOSED                                PASS
history-only torsion                  PASS + evidence
semantic torsion                      HOLD
FLAT_LOOP                             PASS
history holonomy                      PASS + evidence
semantic curvature                    HOLD
invalid/misbinding evidence           FAIL
identity mismatch                     FAIL
policy mismatch                       FAIL
```
