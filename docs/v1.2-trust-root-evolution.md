# v1.2 — Trust-Root Evolution

ATMAN-LATTICE v1.2 separates execution authority from governance authority.

The ordinary execution plane remains:

```text
ATMAN-RUNTIME/1.1
```

Trust-root governance uses a distinct protocol:

```text
ATMAN-TRUST/1.2
```

The reason for the separation is structural: a normal `AuthorityGrant` is already derived from the current trust policy, so using an ordinary grant as the sole authority to replace that policy would make the root of trust authorize its own replacement through the same mechanism it governs.

## Trust policy

A `TrustPolicy` contains:

```text
generation
threshold
roots[] = { key_id, public_key }
previous_policy_hash
activated_at
policy_hash
```

The bootstrap policy may have `previous_policy_hash = null`. Every later policy must link to the exact policy it replaces.

```text
Policy N
   |
   | exact previous_policy_hash
   v
Policy N+1
```

A process restart does not re-bootstrap an already initialized database. Once trust state exists in SQLite, environment roots are bootstrap material only and can no longer silently roll the policy backward.

## Rotation proposal

A rotation binds the exact current policy to the exact next root set:

```text
current policy hash
current generation
next generation = current + 1
next root ids + public keys
next threshold
reason
transition time
```

Each current root signs the digest of that exact transition.

A valid approval therefore cannot be reused for:

- another current policy;
- another next root set;
- another threshold;
- another reason;
- another transition time.

## Quorum

The required quorum is defined by the **current** policy, not the proposed policy.

For a 2-of-3 policy:

```text
Root A ----\
            +--> exact transition --> Policy N+1
Root B ----/
Root C      optional
```

One signature is insufficient. Duplicate signatures from the same key count once and are rejected as duplicate signers.

The next policy may define a different threshold, but that new threshold governs only future transitions after the current quorum has validly activated it.

## Atomic transition

The runtime persists the singleton trust policy in SQLite and performs rotation under `BEGIN IMMEDIATE`:

```text
BEGIN IMMEDIATE
  load Policy N
  verify exact approvals against Policy N
  require current threshold
  construct Policy N+1
  append TrustTransitionReceipt
  update singleton policy
COMMIT
```

Two runtime processes therefore cannot both rotate from the same current generation and commit competing successors through this reference store.

## TrustTransitionReceipt

A successful transition emits an immutable receipt binding:

```text
from_policy_hash
from_generation
to_policy_hash
to_generation
required_threshold
approval_key_ids[]
approval_hashes[]
reason_ref
transitioned_at
transition_hash
```

The receipt records the threshold that was actually required by the previous policy, not merely the threshold configured in the new policy.

## Authority after rotation

Normal v0.8/v0.9 authority verification now reads the persisted trust policy when the runtime database exists.

Therefore, after rotation:

```text
old root + new-generation grant -> REJECT
new root + new-generation grant -> eligible for verification
```

Even if a restarted worker receives the old roots again through bootstrap environment variables, the persisted policy remains authoritative.

## Boundary of the reference model

v1.2 protects trust evolution inside the ATMAN runtime database/process boundary. It does not claim protection against an attacker who can directly rewrite the SQLite database, replace the runtime package, alter the host, or steal enough current root private keys to satisfy quorum.

Production deployments need protected durable storage, key custody/HSMs or equivalent controls, authenticated transport, backup/restore rules for trust state, and operational governance around emergency recovery.

## Core rule

> **The authority to change authority must be proven by the currently valid authority set, recorded as a new generation, and remain distinguishable from ordinary execution permission.**
