# ATMAN-LATTICE v1.5 — Geometric Coherence Gate

v1.5 connects the v1.4 transition-geometry evidence directly to the A3/A4 coherence hierarchy.

This is a discrete engineering model. It is not a claim about physical torsion fields, spacetime curvature, or metaphysical reality.

## Why a gate is needed

v1.4 can prove that transition order matters:

```text
Valid(A) + Valid(B) != Commute(A,B)
```

But detection alone does not answer whether the system should commit, pause, reconcile, or reject.

v1.5 therefore introduces a policy-bound three-valued decision:

```text
PASS  — geometry is acceptable under current policy
HOLD  — local steps may be valid, but global commit requires reconciliation/review
FAIL  — evidence is invalid, identity/policy binding fails, or policy rejects the geometry
```

`HOLD` is intentionally distinct from `FAIL`.

## A3 — geometry-aware cross-axis gate

The existing A3 remains the cryptographic cross-axis binder for A1/A2. The v1.5 `A3-GEOMETRY` gate consumes that A3 result plus exact v1.4 evidence.

```text
A1 + A2
   |
   v
  A3  ---- exact lineage consistency
   |
   +---- TransitionTorsionReceipt
   +---- TransitionCurvatureReceipt
   +---- GeometricCoherencePolicy
   |
   v
A3-GEOMETRY
PASS / HOLD / FAIL
```

The gate re-verifies the exact torsion/curvature evidence. A self-consistent receipt from another path is not sufficient.

## Default policy

The reference policy is conservative without treating path dependence as corruption:

```text
CLOSED                                  -> PASS
SEMANTICALLY_CLOSED_HISTORY_DIVERGENT   -> PASS
TORSION_DETECTED                        -> HOLD
FLAT_LOOP                               -> PASS
SEMANTICALLY_CLOSED_WITH_HOLONOMY       -> PASS
CURVATURE_DETECTED                      -> HOLD
```

A deployment may explicitly escalate these statuses to `FAIL` or relax them to `PASS`; the exact policy is hash-bound into the gate receipt.

## A4 — global geometric coherence

`A4-GEOMETRY` consumes the existing A4 result and one or more geometric observer receipts.

```text
A4 base coherence
      |
      +-- A3-GEOMETRY #1
      +-- A3-GEOMETRY #2
      +-- ...
      |
      v
A4-GEOMETRY
```

Decision severity is monotonic:

```text
PASS < HOLD < FAIL
```

Therefore a `HOLD` cannot be silently collapsed into `PASS`, and a `FAIL` cannot be downgraded by another successful path.

A4 additionally rejects geometric evidence for another identity or another policy hash.

## Central laws

```text
Torsion != Invalidity
HOLD != FAIL
Same semantic state != Same causal history
Self-consistent proof != Proof of this path
Geometric evidence != Execution authority
A3 local consistency != A4 global commit permission
```

The important execution rule is:

> Semantic torsion or curvature may suspend commitment without declaring the underlying transitions false.

This creates an explicit place for reconciliation, simulation, human review, or an incursion-resolution policy.

## Relation to v1.3

A typical route is:

```text
Transition geometry
      |
      v
A3-GEOMETRY = HOLD
      |
compatibility evaluation
      |
      +-- compatible under explicit policy -> preserve both paths
      +-- incompatible -> IncursionReceipt -> reconcile/isolate/merge/reject
```

So torsion is evidence about path dependence; incursion is evidence about coexistence.

They are related but not interchangeable.

## Security boundary

The gate verifies evidence and policy binding. It does not itself grant execution authority. Runtime execution still requires the authority and capability layers introduced in v0.8–v1.2.
