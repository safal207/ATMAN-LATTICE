# ATMAN-LATTICE v0.5 — Replay, Restore, and Branch Identity

## Goal

v0.5 formalizes what happens when a system returns to a historical checkpoint and continues from there.

The core rule is:

> **Restore is not continuation.**

A restored checkpoint may preserve identity ancestry, but it must not silently impersonate the current head of the source branch.

## Restore transition

Let a source checkpoint be:

```text
identity = I
branch = B7
generation = 7
lineage_root = R7
receipt = Hn
```

A valid restore creates:

```text
identity = I
target branch = B8 != B7
target generation = 8 > 7
target lineage root = R8 != R7
```

while preserving an explicit cryptographic edge back to the historical source receipt.

```text
source checkpoint Hn
        │
        │ RestoreReceipt
        ▼
new branch genesis H0'
```

## Why a new lineage root?

The restored state may contain information copied from the past, but its future is not the future that originally followed that checkpoint.

Therefore:

```text
same identity ancestry
!=
same branch history
```

A new root prevents the restored execution from being composed with observer or authorization artifacts that belong to the old branch head.

## RestoreReceipt

The restore receipt commits to:

```text
identity_ref
source_branch_ref
source_generation
source_lineage_root_hash
source_receipt_hash
source_state_ref
source_sequence
target_branch_ref
target_generation
target_lineage_root_hash
target_genesis_receipt_hash
replayed_at
```

and derives `restore_hash` from the canonical form.

## Executable rules

`restore_checkpoint()` requires:

1. source receipt integrity is valid;
2. target branch differs from the source branch;
3. target generation is strictly greater than source generation;
4. target genesis gets a new cryptographic lineage root;
5. target provenance contains the exact source receipt hash;
6. `RestoreReceipt` binds source checkpoint and target genesis together.

`verify_restore()` rejects substitution of another target branch/genesis, changed source metadata, missing provenance, non-advancing generation, and branch/root reuse.

## Temporal interpretation

Using the ATMAN-LATTICE temporal axis:

```text
S4 past checkpoint
      │
      │ A2 / restore edge
      ▼
S5' new future branch
```

The new future `S5'` is causally descended from `S4`, but it is not identical to the future that was previously reached from `S4`.

Thus:

> **Past may be revisited as an origin, but the resulting future must remain distinguishable from the future that already occurred.**

## Non-goals

v0.5 does not yet define merge semantics between restored branches, distributed consensus over competing futures, or one-time execution-token consumption. Those remain later protocol layers.
