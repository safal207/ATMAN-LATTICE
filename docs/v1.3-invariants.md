# v1.3 Multiverse Invariants

## I-77 — Potentiality Is Not History

> A represented future is not committed history until an explicit commit artifact creates a lineage from it.

```text
Potential(x) != Committed(x)
```

Planning, simulation, ranking, or consideration must not mutate historical lineage by implication.

## I-78 — Exact Potential Commit Binding

> A committed branch must bind to the exact potential and exact proposed payload that authorized its creation.

```text
commit.potential_hash = potential.potential_hash
commit.payload_digest = potential.payload_digest
```

A plan approved as A cannot silently commit B.

## I-79 — Commit Creates a Distinct Lineage

> Committing a potential creates a new branch, generation, and cryptographic lineage root rather than silently extending the source world.

```text
target.branch != source.branch
target.generation > source.generation
target.root != source.root
```

## I-80 — Plurality Is Not Incoherence

> The existence of multiple valid branches is not itself a coherence failure.

```text
Valid(A) && Valid(B) !=> InvalidSystem
```

Branches may remain distinguishable and valid without being collapsed into one history.

## I-81 — Validity Does Not Imply Coexistence

> Two individually valid worlds may be mutually incompatible in one execution context.

```text
Valid(A) && Valid(B) !=> Coexist(A, B)
```

Compatibility requires its own evidence.

## I-82 — Incursion Must Be Explicit

> Cross-branch incompatibility must be represented as an explicit receipt over exact branch heads and lineage roots.

An `INCOMPATIBLE` verdict must name a non-`NONE` resolution mode. Silent overwrite is not a resolution.

## I-83 — Compatible Worlds Must Not Invent Destructive Resolution

> A `COEXIST` verdict must preserve plurality and therefore uses `NONE` as its resolution mode.

Coexistence is not an excuse to merge, prune, or rewrite branches.

## I-84 — Composite Narrative Non-Erasure

> A composite result must preserve exact references to every parent history from which it was produced.

```text
Composite(C) => Parents(C) preserved
```

Rehashing a rewritten narrative envelope does not make the rewrite valid; verification compares the composite artifact with actual parent receipts and the merge receipt.

## I-85 — Keeper Is Not Sovereign

> A keeper that can preserve or classify histories does not thereby gain authority to rewrite their ancestry.

```text
Preserve(Worlds) != AuthorityToRewrite(Worlds)
```

This keeps global coherence separate from narrative ownership.

## Minimal v1.3 acceptance rule

```text
potential_commit_binding      = valid
committed_lineage_fork        = valid
cross_branch_compatibility    = explicit
incompatibility_resolution    = explicit_if_needed
left_parent_preserved         = valid
right_parent_preserved        = valid
composite_lineage_distinct    = valid
```

A system fails v1.3 if it treats contemplated actions as executed history, silently changes an approved future during commit, assumes individually valid branches must coexist, or produces a composite state that erases a parent history.
