# v1.6 Invariants — Verification Pressure

These invariants extend ATMAN-LATTICE with explicit semantics for finite verification capacity.

## I-106 — Unverified Is Not Invalid

> A work item that was not processed because verification capacity was exhausted must not acquire a semantic FAIL verdict merely from non-processing.

```text
DEFERRED != FAIL
```

## I-107 — Capacity Is Admission, Not Truth

> Capacity policy decides what can be checked in the current verification window; it does not decide which branch, path, or claim is true.

```text
capacity_decision != semantic_verdict
```

## I-108 — Complete Pressure Accounting

> Every offered verification work item must appear exactly once as admitted, capacity-deferred, or oversized-deferred.

For offered set `W`:

```text
W = ADMITTED ∪ DEFERRED_CAPACITY ∪ DEFERRED_OVERSIZED
```

and the three sets are pairwise disjoint.

## I-109 — No Silent Pruning Under Pressure

> Overload must not make a work item disappear from the verification record.

A branch or path may remain pending, but its required verification evidence must remain traceable.

## I-110 — Deterministic Scheduling

> The same offered set, policy, and measurement time must produce the same rank order and admission result regardless of input iteration order.

This makes pressure decisions replayable and inspectable.

## I-111 — Aging Against Starvation

> Waiting time must be able to increase effective scheduling priority under the configured aging policy.

```text
effective_priority = base_priority + floor(wait_time / aging_quantum)
```

This does not guarantee that work larger than total capacity can ever execute.

## I-112 — Oversized Work Preservation

> A work item whose declared cost exceeds the whole capacity window must remain explicitly classified as oversized-deferred rather than being dropped or labeled invalid.

```text
cost(work) > total_capacity
=> DEFERRED_OVERSIZED
```

## I-113 — Admission Is Not Completion

> An admitted verification item is still pending until completion evidence exists.

```text
ADMITTED != VERIFIED
```

## I-114 — Incomplete Required Coverage Holds Global Commit

> If any required verification item is pending or deferred, a provisional global PASS must become HOLD rather than PASS or FAIL.

```text
base = PASS
and required verification incomplete
=> HOLD
```

## I-115 — Deferred Work Cannot Be Claimed Completed

> Completion evidence is valid only for work actually admitted by the exact pressure receipt.

```text
completed(work) and work not in ADMITTED
=> FAIL
```

This blocks a caller from bypassing capacity accounting by claiming a deferred check was completed elsewhere without a new verified admission/coverage relation.

## Acceptance summary

A pressure-aware global PASS requires:

```text
pressure_receipt_integrity = valid
all_required_work_accounted = true
all_required_work_admitted = true
all_admitted_work_completed = true
no_deferred_required_work = true
base_decision = PASS
```

Otherwise:

```text
invalid evidence / impossible completion claim -> FAIL
valid but incomplete verification              -> HOLD
```
