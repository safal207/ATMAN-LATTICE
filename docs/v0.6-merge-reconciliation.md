# ATMAN-LATTICE v0.6 — Branch Merge / Reconciliation

Version `0.6.0` defines how two valid future branches may be reconciled without pretending that either branch never existed.

## Core rule

> **Merge is a new lineage, not the erasure of either parent lineage.**

Given a common ancestor `A` and two independently valid restored futures:

```text
                -> L0 -> L1 -> L2
A -------------<
                -> R0 -> R1 -> R2
```

a merge creates a third branch:

```text
                -> L0 -> L1 -> L2 --\
A -------------<                    +-> M0 -> M1 ...
                -> R0 -> R1 -> R2 --/
```

`L` and `R` remain independently addressable histories. `M0` is a new genesis with a new branch, generation, and lineage root.

## Required ancestry proof

The v0.6 harness requires both parent branches to carry valid `RestoreReceipt` proofs from the **same exact source checkpoint**.

For left and right parents:

```text
left_restore.source_receipt_hash  == ancestor.receipt_hash
right_restore.source_receipt_hash == ancestor.receipt_hash
```

and both restored branch chains must independently pass `verify_lineage_chain()`.

This prevents unrelated branches that merely share the same human-readable identity label from being merged as one history.

## Conflict completeness

A merge conflict is represented by:

```text
conflict_ref
left_digest
right_digest
```

Every declared conflict must have exactly one `ConflictResolution`:

```text
conflict_ref
left_digest
right_digest
strategy = LEFT | RIGHT | SYNTHESIZED
result_digest
reason_ref
```

The resolution set is canonicalized and hashed into `resolution_digest`.

The merge is rejected when:

- a conflict has no resolution;
- a resolution has no matching conflict;
- a resolution binds to different left/right digests;
- `LEFT` does not select the left digest;
- `RIGHT` does not select the right digest;
- any committed resolution is substituted after merge creation.

## Merge target

A valid target must satisfy:

```text
target_branch != ancestor_branch
target_branch != left_branch
target_branch != right_branch

target_generation > max(left_generation, right_generation)

target_lineage_root != left_lineage_root
target_lineage_root != right_lineage_root
```

The target genesis commits to:

```text
common ancestor receipt + root
left head receipt + root
right head receipt + root
resolution_digest
merged_payload_digest
```

and preserves explicit provenance references to both parent heads and the common ancestor.

## What v0.6 does not claim

The protocol proves structural ancestry and explicit reconciliation decisions. It does **not** prove that a chosen conflict resolution is morally correct, optimal, or semantically truthful.

It only makes the merge decision inspectable and tamper-evident.

## Principal counterexample

Two branches can each be valid and belong to the same identity ancestry while still being unsafe to merge automatically:

```text
Left  = valid future
Right = valid future
same ancestor = true

but unresolved_conflicts > 0

=> MERGE REJECTED
```

Therefore:

> **Compatible ancestry is necessary for merge; resolved contradiction is necessary for coherence.**
