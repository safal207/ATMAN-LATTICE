# v1.15 Invariants — Held-Out Structural Validation

## I-263 — Selection / Evaluation Separation
A dependency sample used to evaluate a structural candidate MUST NOT be used in that candidate's selection replay.

```text
SelectionData != EvaluationData
```

## I-264 — Deterministic Partition
The reference held-out partition is derived deterministically from immutable sample hashes and the registered policy. Client requests do not supply a per-run random salt.

## I-265 — Partition Completeness
Every dependency-pair sample in the bound history MUST belong to exactly one of selection or evaluation.

## I-266 — Selection Replay Isolation
A `StructuralValidationCandidate.selection_replay` MUST bind exactly the candidate's selection sample hashes.

## I-267 — Selection Improvement Is Necessary, Not Sufficient
A candidate MUST improve selection replay before held-out validation, but selection improvement alone MUST NOT authorize structural apply.

## I-268 — Better Replay Is Not Better Generalization
A candidate that improves selection replay but fails to improve held-out raw Brier score MUST produce `OVERFIT_SIGNAL`.

```text
BetterReplay != BetterGeneralization
```

## I-269 — Complexity Cost Is Explicit
Structural complexity penalties MUST be represented in an explicit validation policy and preserved in the validation receipt.

## I-270 — More Edges Are Not More Knowledge
A raw held-out improvement that is erased by the configured edge penalty MUST produce `COMPLEXITY_REJECTED`.

```text
MoreEdges != MoreKnowledge
```

## I-271 — Complexity Policy Is Not Truth
Changing `edge_penalty_ppm` may change structural preference but MUST NOT rewrite historical observations or claim a causal fact.

## I-272 — Held-Out Validator Independence
The held-out validator MUST NOT be the candidate proposer.

## I-273 — Complete Current Candidate Set
Structural selection MUST consider all currently held-out-validated candidates sharing the exact subject, pair, base graph, policy, and history context. A client MUST NOT choose an arbitrary subset.

## I-274 — Deterministic Winner
Among eligible candidates, the winner MUST be the candidate with the greatest positive regularized held-out improvement, with deterministic hash tie breaking.

## I-275 — No Eligible Candidate Is Not World Failure
`NO_ELIGIBLE_CANDIDATE` means no current candidate passed the configured gate. It MUST NOT imply that no real dependency exists.

## I-276 — Selected Is Not Applied
A selection receipt MUST NOT itself mutate the dependency graph.

```text
Selected != Applied
```

## I-277 — Reviewer Independence
The structural selection reviewer MUST be distinct from the selector and the selected candidate proposer.

## I-278 — New Evidence Invalidates Old Selection
If dependency-pair history changes after selection, the old selection MUST NOT authorize apply.

```text
OldHistory != CurrentSelectionAuthority
```

## I-279 — New Validated Competitor Invalidates Old Selection
If the complete current validated-candidate set changes after selection, the old selection MUST NOT authorize apply.

```text
OldCandidateSet != CurrentSelectionAuthority
```

## I-280 — Validation Policy Is Immutable In-Place
The reference runtime MUST NOT silently rewrite the registered structural validation policy for a subject.

## I-281 — Base Graph Freshness
Validated apply MUST require the current graph hash to equal the base graph bound by the selected candidate and selection receipt.

## I-282 — Exact Validation Binding
Apply MUST use the exact held-out validation selected by the structural selection receipt.

## I-283 — Held-Out Improvement Required At Apply
Only `HELDOUT_IMPROVED` with positive regularized improvement may reach validated structural apply.

## I-284 — Old And New Graphs Are Preserved
Successful apply MUST preserve both the old graph and the new graph in durable revision history.

## I-285 — Failed Candidates Are Not Erased
`OVERFIT_SIGNAL`, `COMPLEXITY_REJECTED`, and insufficient candidates remain historical evidence and MUST NOT be silently pruned by selection.

## I-286 — Held-Out Fit Is Not Causality
A successful held-out structural result establishes only performance under the bound statistical evaluation procedure.

```text
HeldOutImprovement != CausalityProof
RegularizedSelection != Truth
```
