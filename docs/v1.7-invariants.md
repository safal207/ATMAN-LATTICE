# v1.7 Runtime Verification Plane — Invariants

## I-116 — Verification Debt Durability
Submitted/deferred verification work must survive worker-process restart while the authoritative runtime database survives.

## I-117 — Runtime-Owned Admission Policy
Client input must not replace the server-owned verification capacity policy used by the scheduler.

## I-118 — Admitted Is Not Verified
Admission into a capacity window does not constitute completed verification.

```text
ADMITTED != VERIFIED
```

## I-119 — Deferred Is Not Pruned
Capacity deferral or oversized deferral must preserve the work item as unresolved verification debt.

```text
DEFERRED != INVALID
DEFERRED != DELETED
```

## I-120 — Completion Requires Current Admission
A completion receipt may be created only for work admitted by the current pressure window.

## I-121 — Completion Result Preservation
Completion carries PASS/HOLD/FAIL. Completion itself must never be interpreted as PASS.

```text
COMPLETED != PASS
```

## I-122 — Incomplete Coverage Holds Global Commitment
Pending or deferred required verification work must prevent a runtime geometric PASS.

```text
required work incomplete => HOLD
```

unless an independently stronger failure already exists.

## I-123 — Failed Verification Dominates Coverage
If any completed required verification returns FAIL, complete coverage must not turn that result into PASS.

## I-124 — Explicit HOLD Discharge
A geometric HOLD may become PASS only when it has explicit required verification work and the complete required set resolves to PASS.

A HOLD with no verification work remains HOLD.

## I-125 — Preview Is Not Finalization
A diagnostic runtime decision is not an authoritative final decision.

```text
preview != finalization
```

## I-126 — Stable State / Variable Observation Time Separation
The state used for use-time finalization must have a stable digest independent of observation timestamp. The time-stamped receipt may change as time changes, but the state digest must change only when relevant verification state changes.

## I-127 — Stale Preview Rejection
Finalization must recompute current verification state and reject a keeper proof bound to an older state digest.

```text
state(S0) -> preview
state changes -> S1
finalize(S0) => REJECT
```

## I-128 — Keeper Authority Separation
Only a currently valid `VERIFICATION_KEEPER` authority proof over the exact current decision state may create a finalization receipt.

Submission or execution authority alone is insufficient.

## I-129 — Exact Completion Binding
A completion must bind exact work, target gate, schedule generation, pressure hash, result evidence, actor, and runtime time.

## I-130 — Verifier Capacity Is Not Reality Capacity
Exhaustion of verification capacity is evidence about the observer system, not evidence that deferred branches are false.

```text
VerifierCapacity != RealityCapacity
```
