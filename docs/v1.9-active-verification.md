# v1.9 — Information Gain / Active Verification

v1.9 adds a process-separated active-verification plane that chooses which verification work is expected to reduce uncertainty most efficiently under finite budget.

It does **not** turn information value into truth, permission, or a verification verdict.

```text
ATMAN-RUNTIME/1.1  privileged execution
ATMAN-TRUST/1.2    trust governance
ATMAN-VERIFY/1.7   verification debt / completion / finalization
ATMAN-ECONOMY/1.8  measured verification cost / budget allocation
ATMAN-ACTIVE/1.9   uncertainty model / expected information gain / next-check selection
```

## Core law

```text
ExpectedInformationGain != Truth
Selected != Verified
LowExpectedGain != Invalid
```

The active plane answers only:

> Given the current explicit uncertainty model and current estimated verification cost, which available check is expected to reduce uncertainty most per unit of verification budget?

It does not answer whether the hypothesis is true.

## Binary hypothesis state

The v1.9 reference core starts with an explicit binary proposition:

```text
HypothesisState
  hypothesis_ref
  subject_identity_ref
  true_probability_bps
  evidence_state_hash
  generation
  hypothesis_hash
```

Probability is stored as integer basis points `0..10000`. The state is generation-bound and commits the evidence state from which the prior was derived.

A probability is therefore not accepted as ambient truth. It is an explicit, versioned model input.

## Verification likelihood model

Each verification candidate may have a model:

```text
VerificationLikelihoodModel
  candidate_hash
  hypothesis_hash
  positive_if_true_bps
  positive_if_false_bps
  model_ref
  model_generation
  model_hash
```

The exact candidate and exact hypothesis generation are committed into the model.

If the hypothesis changes, the old likelihood model becomes stale by construction:

```text
Hypothesis H1 -> Likelihood L(H1)
Hypothesis H2
L(H1) cannot be evaluated as L(H2)
```

## Expected information gain

The reference implementation uses binary Shannon entropy:

\[
H(p)=-p\log_2 p-(1-p)\log_2(1-p).
\]

For a candidate test with explicit likelihoods, the system computes:

\[
EIG = H(prior)-E[H(posterior\mid outcome)].
\]

The result is quantized into integer microbits for receipt material.

`ExpectedInformationGainReceipt` commits:

```text
candidate
hypothesis
likelihood model
prior entropy
expected posterior entropy
expected information gain
estimated verification cost
information / cost ratio
computation time
```

The Shannon calculation is a reference-model calculation over explicit probabilistic assumptions. It is not evidence that those assumptions are empirically calibrated.

## Cost remains v1.8 accounting

Active verification reuses v1.8 cost estimators:

```text
CostObservationReceipt -> CostEstimatorSnapshot -> estimated_cost_units
```

The declared submitter cost is still not treated as accounting truth.

Ranking therefore uses the combination:

\[
ExpectedInformationGain / EstimatedVerificationCost.
\]

Optional policy terms may also add aging and risk weight. Those terms influence scheduling only; they do not modify the information-gain receipt itself.

## Explicit dispositions

Modeled candidates are classified as:

```text
SELECTED
DEFERRED_BUDGET
DEFERRED_OVERSIZED
DEFERRED_LOW_INFORMATION
```

The runtime additionally preserves candidates without a current hypothesis/likelihood pair as:

```text
UNMODELED
```

Unmodeled work is not dropped and not called invalid.

## Runtime plane

Reference worker:

```bash
python -m model.active_worker
```

Protocol:

```text
ATMAN-ACTIVE/1.9
```

Operations:

```text
register_hypothesis_state
register_likelihood_model
preview_active_plan
finalize_active_plan
get_active_state
```

Roles:

```text
ACTIVE_VERIFICATION_MODEL_KEEPER
ACTIVE_VERIFICATION_PLAN_KEEPER
```

Model registration is bound to the verification identity scope. Plan finalization is bound to the global active-verification scope.

## Server-owned active state

SQLite persists:

```text
active_hypothesis
active_likelihood_model
active_verification_plan
```

The runtime active-state digest commits:

```text
current economy state
current incomplete candidate set
current hypothesis hashes
current likelihood-model hashes
active policy
v1.8 economy policy
```

If any of those change between preview and finalization:

```text
preview S0
knowledge/economy state -> S1
finalize(S0)
  -> REJECT stale active verification state
```

This extends use-time binding to the state of knowledge itself.

## Deliberate boundaries

v1.9 does not claim:

- that a registered prior is objectively correct;
- that likelihoods are automatically calibrated;
- that higher expected information gain means a hypothesis is more true;
- that selection authorizes execution;
- that selection completes verification;
- that low expected information gain makes work invalid;
- that the current binary model is a universal uncertainty representation.

Production systems should ground hypothesis/likelihood updates in calibrated evidence, protected telemetry, reproducible datasets, or independently governed model updates.
