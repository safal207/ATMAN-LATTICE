# ATMAN-LATTICE v1.14 Invariants

## I-239 — Correlation Challenge Is Not Causality Proof

```text
CorrelationChallenge != CausalityProof
```

A statistical dependency signal may justify a structural proposal but cannot prove a physical or ontological causal arrow.

## I-240 — Structural Proposal Is Not Structural Mutation

```text
Proposal != Mutation
```

Creating a graph proposal does not change the active dependency graph.

## I-241 — Graph Edges Mean Statistical Conditioning Only

The v1.14 edge relation is exactly `STATISTICAL_CONDITIONING`. A `CAUSES` relation is outside this protocol.

## I-242 — Direction Is Explicit

A challenged independence relationship may produce competing `LEFT_TO_RIGHT` and `RIGHT_TO_LEFT` proposals. Direction must not be inferred silently.

## I-243 — Dependency Graph Is Acyclic

The reference graph must remain a DAG. A proposal that creates a cycle is rejected before issuance.

## I-244 — Structural Generation Is Monotonic

An accepted proposal targets exactly:

```text
Graph N -> Graph N+1
```

## I-245 — Structural Proposal Binds Exact Base Graph

A proposal binds the exact base graph hash and generation. It cannot be replayed or applied to another graph generation.

## I-246 — Structural Proposal Requires Calibration Challenge

Adding a conditional edge requires `INDEPENDENCE_CHALLENGED`. Removing a declared conditional edge requires `CONDITIONAL_DEPENDENCY_NOT_OBSERVED`.

## I-247 — Replay Uses Preserved Historical Samples

Structural replay binds the exact dependency pair sample hashes and preserves per-case scores.

## I-248 — Replay Uses Leave-One-Out Evaluation

Each scored historical case is predicted from the remaining history rather than from a statistic containing the case itself.

## I-249 — Historical Structural Fit Is Not Causality

```text
ReplayImprovement != CausalityProof
```

Better historical predictive structure is not proof of a real-world mechanism.

## I-250 — Historical Structural Fit Is Not Future Truth

```text
HistoricalStructuralFit != FutureTruth
```

An improved replay does not guarantee future predictive performance.

## I-251 — Approval Requires Improved Replay

`APPROVE` is invalid unless structural replay status is `STRUCTURE_IMPROVED`.

## I-252 — Reviewer Is Independent From Proposer

```text
StructuralProposer != StructuralReviewer
```

The actor proposing a graph change cannot review the same proposal.

## I-253 — Review Is Not Apply

```text
APPROVE != Mutation
```

Approval is evidence for a later privileged apply operation, not the mutation itself.

## I-254 — Structural Authority Is Separated

```text
DEPENDENCY_GRAPH_BOOTSTRAP_KEEPER
!= STRUCTURAL_GRAPH_REVISION_PROPOSER
!= STRUCTURAL_GRAPH_REPLAY_KEEPER
!= STRUCTURAL_GRAPH_REVISION_REVIEWER
!= STRUCTURAL_GRAPH_REVISION_APPLIER
```

## I-255 — Bootstrap Is Not Ongoing Rewrite Authority

A graph generation 0 bootstrap may initialize a missing subject graph. It cannot overwrite an existing graph.

## I-256 — Apply Revalidates Historical Evidence

Apply must recompute replay from current dependency-pair history.

```text
OldStructuralReplay != CurrentStructuralRevisionAuthority
```

## I-257 — New Pair History Makes Old Replay Stale

If the exact replay sample/case set changes after review, old apply authority is rejected.

## I-258 — Competing Proposals Preserve Plurality Until Apply

Multiple direction proposals may exist against the same base graph. Applying one does not erase the others; it makes their old base generation stale.

## I-259 — Applied Graph Revision Preserves Both Graph Generations

The runtime stores complete old and new graph material in append-only revision history.

```text
LearningStructure != ErasingPriorStructure
```

## I-260 — Structural Graph Does Not Rewrite Event Provenance

A graph revision does not retroactively alter v1.11 evidence dependency receipts, accepted evidence, source-event hashes, or parent evidence hashes.

## I-261 — Graph Model Does Not Grant Execution Authority

A structural dependency edge, replay, review, or revision receipt does not grant tool execution, A4 finalization, trust mutation, or evidence-verification authority.

## I-262 — Statistical Structure Remains a Model

```text
ValidGraphReceipt != ProvenPhysicalCausality
```

Cryptographic validity proves what graph the system committed and how it changed, not that the graph is an infallible description of the external world.
