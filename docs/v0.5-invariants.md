# ATMAN-LATTICE v0.5 — Additional Replay Invariants

These invariants extend the v0.4 set in `INVARIANTS.md`.

## I-24 — Restore Is Not Continuation

> A historical checkpoint restored for new execution must not silently re-enter the source branch as if no divergence occurred.

A valid restore requires:

```text
target_branch_ref != source_branch_ref
```

The restored state may inherit identity ancestry while beginning a distinct history.

## I-25 — Restore Generation Advance

> A restore that creates a new executable future must advance the generation marker.

```text
target_generation > source_generation
```

This prevents stale artifacts from the old generation from being treated as current merely because the restored state resembles an earlier state.

## I-26 — Restored Lineage Fork

> A restored branch must receive a new cryptographic lineage root while retaining an explicit proof edge to the source checkpoint.

```text
target_lineage_root_hash != source_lineage_root_hash
```

and the target genesis must preserve the exact source receipt hash as provenance.

Thus:

```text
same identity ancestry != same history
```

## I-27 — Historical Future Non-Erasure

> Creating a new future from an earlier checkpoint must not erase, overwrite, or retroactively redefine the future that already followed that checkpoint.

If a source history is:

```text
S0 -> S1 -> S2 -> S3
```

and the system restores from `S1`, the result is:

```text
S0 -> S1 -> S2 -> S3
       |
       +-> S2' -> S3' ...
```

not:

```text
S0 -> S1 -> S2' -> S3'
```

unless an explicit destructive-history operation with separate governance is defined.

## v0.5 acceptance additions

A restore is provisionally admissible only when:

```text
source_receipt_integrity = valid
source_checkpoint_binding = exact
target_branch_is_new = true
target_generation_advanced = true
target_lineage_root_is_new = true
source_provenance_preserved = true
restore_receipt_integrity = valid
```

The principal v0.5 counterexample is:

```text
same identity
same checkpoint content
but restored into same branch/generation
=> REJECT
```

because semantic similarity of state does not authorize rewriting history.
