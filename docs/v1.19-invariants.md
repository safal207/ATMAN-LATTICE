# ATMAN-LATTICE v1.19 — Drift-Governed Remediation Invariants

v1.19 consumes an acknowledged v1.18 `PERSISTENT_DRIFT_SIGNAL` and governs what the system may do next. Drift is an observation about a confirmed model under later evidence; it is not itself rollback authority.

## I-371 — Persistent Drift Is a Trigger, Not a Command

`PersistentDriftSignal != RemediationDecision`

A persistent signal opens a governed decision surface. It does not select an action.

## I-372 — Persistent Drift Is Not Automatic Rollback

`PersistentDrift != AutomaticRollback`

Rollback requires its own proposal, assessment, selection, review, and apply authority.

## I-373 — Remediation Requires the Current Persistent-Drift Snapshot

A proposal binds one exact v1.18 `ReplicationSeriesSnapshot` whose signal is `PERSISTENT_DRIFT_SIGNAL`.

## I-374 — New Replication Evidence Stales Old Remediation Authority

If the replication evaluation/review set changes, an old remediation snapshot cannot authorize review or apply.

`OldRecoveryChoice != CurrentRecoveryAuthority`

## I-375 — Recovery Alternatives Remain Explicit

The reference vocabulary keeps five alternatives distinct:

```text
HOLD
COLLECT_MORE_DATA
PARAMETER_REVISION
STRUCTURAL_REVISION
SAFE_ROLLBACK
```

No alternative is silently rewritten into another.

## I-376 — Competing Remediation Proposals Share One Frozen Context

All proposals considered in one selection bind the same target, snapshot, confirmed revision, current graph, and latest replication evaluation.

## I-377 — Every Current Proposal Must Be Assessed Before Selection

The runtime selection binds the complete current proposal set and one assessment per proposal.

`UnassessedAlternative != SelectableAlternative`

## I-378 — Assessment Is Separate From Proposal

`Proposer != Assessor`

The actor proposing a recovery path cannot issue its assessment.

## I-379 — Latest Replication Evaluator Is Not the Remediation Assessor

The actor who produced the latest drift evaluation cannot also provide the remediation assessment used for selection.

## I-380 — Drift Is Not Evidence for Rollback by Itself

`Drift != EvidenceForRollback`

A rollback assessment uses the observed performance of the confirmed graph against its exact pre-confirmation base graph.

## I-381 — Safe Rollback Requires Non-Positive Current Structural Advantage

In the strict v1.19 reference policy, `SAFE_ROLLBACK` is supported only when the latest replication regularized improvement of the current confirmed structure over its base is `<= 0`.

## I-382 — Performance Drift Alone Does Not Justify Rollback

A model may degrade relative to its earlier performance while still outperforming the base graph. That condition routes to observation/revision choices rather than automatic rollback.

## I-383 — Unsupported Rollback Cannot Be Selected

`ROLLBACK_UNSUPPORTED` is a preserved assessment result, not an eligible recovery action.

## I-384 — Selection Is Separate From Assessment

`Assess != Select`

The selector chooses among assessed alternatives and binds the full candidate/assessment set.

## I-385 — Selector Independence

The selector cannot be the proposer or assessor of the selected path.

## I-386 — Review Is Separate From Selection

`Select != Review`

A selected remediation path still needs a distinct review decision.

## I-387 — Reviewer Independence

The reviewer cannot be the selected proposer, assessor, or selector.

## I-388 — Approval Is Not Apply

`RemediationApproval != RemediationApply`

An `APPROVE` review does not mutate the graph by itself.

## I-389 — Applier Independence

The remediation applier cannot be the selected proposer, assessor, selector, or reviewer.

## I-390 — One Snapshot Gets At Most One Remediation Execution

The reference runtime persists at most one execution for one exact persistent-drift snapshot.

## I-391 — HOLD Is an Explicit Non-Mutation

`HOLD` records a governed decision while leaving the current graph unchanged.

## I-392 — COLLECT_MORE_DATA Is an Explicit Non-Mutation

The system may deliberately defer model change and request additional replication evidence.

`CollectMoreData != ModelMutation`

## I-393 — Parameter Revision Does Not Bypass v1.13

Selecting `PARAMETER_REVISION` yields `DOWNSTREAM_GOVERNANCE_REQUIRED` with `ATMAN-REVISION/1.13` as the downstream protocol.

`RemediationApproval != ParameterRevisionApproval`

## I-394 — Structural Revision Does Not Bypass v1.14

Selecting `STRUCTURAL_REVISION` yields `DOWNSTREAM_GOVERNANCE_REQUIRED` with `ATMAN-GRAPH/1.14` as the downstream protocol.

`RemediationApproval != StructuralRevisionApproval`

## I-395 — Safe Rollback Is a Forward Revision

A rollback never decrements the graph generation.

```text
Graph N (confirmed)
   ↓ remediation
Graph N+1 with topology copied from the exact pre-confirmation Graph N-1
```

## I-396 — Rollback Restores Topology, Not History

`ForwardRollback != HistoryRewrite`

The new graph receives a new evidence-state hash bound to the drift snapshot, proposal, assessment, selection, and review.

## I-397 — Former Confirmed State Remains Preserved

The execution receipt binds both the former confirmed graph hash and the rollback-source graph hash.

## I-398 — Recovery Choice Does Not Erase Former Validity

`RecoveryChoice != ErasureOfFormerValidity`

A model may have been supported by earlier confirmation and later cease to generalize. Both facts remain auditable.

## I-399 — Current Graph Freshness Is Rechecked at Apply

If another governed graph revision has already changed the current graph, the old remediation chain cannot mutate it.

## I-400 — Remediation Does Not Diagnose Drift Cause

`DriftKind != DriftCause`

Structural/performance drift labels describe observed scoring behavior; they do not prove why the environment changed.

## I-401 — Remediation Does Not Prove Causality

No remediation receipt upgrades `STATISTICAL_CONDITIONING` into a physical or causal claim.

## I-402 — Remediation Monitoring Authority Is Not General Execution Authority

v1.19 receipts authorize no tool execution, trust-root changes, unrelated state mutations, or external side effects.

## I-403 — Remediation Policy Is Explicit and Immutable in the Reference Runtime

Allowed recovery actions and rollback strictness are committed before a remediation decision is executed.

## I-404 — A Rolled-Back Graph Must Earn Future Confidence Again

A successful `FORWARD_ROLLBACK` invalidates the old v1.18 target as current-model status. The new graph must enter the appropriate verification/confirmation/replication lifecycle rather than inheriting permanent confidence from the older target.
