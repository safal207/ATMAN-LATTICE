# ATMAN-LATTICE v1.14 — Structural Dependency-Graph Revision

v1.14 extends calibration-governed parameter revision into governed **structural** revision of the observer's dependency graph.

The central boundary is:

```text
CorrelationChallenge != CausalityProof != StructuralMutation
```

A dependency calibration signal may justify proposing a different statistical conditioning structure. It does not prove a real-world causal arrow and it does not directly mutate the active graph.

## Graph semantics

`DependencyGraphState` is a versioned directed acyclic graph whose edges mean only:

```text
STATISTICAL_CONDITIONING
```

The reference model deliberately has no `CAUSES` edge type.

A graph edge:

```text
parent_model_ref -> child_model_ref
```

means that future statistical modeling may condition the child signal on the parent signal. It is not an ontological claim that the parent physically causes the child.

## Competing direction proposals

When v1.12 reports `INDEPENDENCE_CHALLENGED` for two signal families, v1.14 does not infer direction automatically.

The same challenge can produce competing proposals:

```text
L -> R
R -> L
```

Both proposals bind the same historical dependency challenge and the same base graph generation. They are alternative statistical structures, not causal conclusions.

## Acyclicity

The active reference graph is a DAG. Proposed edges are validated before proposal issuance.

```text
A -> B -> C
C -> A
```

is rejected because it closes a cycle.

This is a modeling constraint of the v1.14 reference layer, not a claim that feedback systems cannot exist in reality. Cyclic/dynamic graphical models require a later explicit model rather than silently weakening DAG semantics.

## Structural replay

A structural proposal must be replayed on historical `DependencyPairSample` receipts.

The replay uses leave-one-out prediction to reduce trivial self-fit:

```text
for each resolved pair sample i:
    train empirical rates on all samples except i
    score base structure on i
    score proposed structure on i
```

An independent structure predicts the child from the remaining marginal child-positive rate.

A conditional structure predicts the child from the remaining child-positive rate among observations with the same parent outcome.

Both are scored with deterministic binary Brier score.

The replay reports:

```text
INSUFFICIENT_REPLAY
STRUCTURE_IMPROVED
NO_STRUCTURE_IMPROVEMENT
```

Only `STRUCTURE_IMPROVED` can be approved.

```text
HistoricalStructuralFit != CausalityProof
HistoricalStructuralFit != FutureTruth
```

## Review and apply

The structural revision chain is:

```text
DependencyCalibrationSnapshot
    -> StructuralGraphRevisionProposal
    -> StructuralGraphReplayReceipt
    -> StructuralGraphReviewReceipt
    -> DependencyGraphRevisionReceipt
```

Proposal, replay, review, and apply use separate authority roles.

The reviewer must be distinct from the proposer.

An `APPROVE` review still does not mutate the graph. Apply is a separate privileged operation.

## Use-time freshness

At apply time, the runtime recomputes structural replay from the current dependency-pair history.

If new calibration samples appeared after review, the old replay is stale and apply is rejected:

```text
OldStructuralReplay != CurrentStructuralRevisionAuthority
```

The current graph hash/generation must also still match the proposal's exact base graph.

Therefore two competing proposals from the same base can coexist historically, but applying one makes the other's base stale.

## History preservation

Successful apply creates:

```text
Graph generation N -> Graph generation N+1
```

and stores both complete graph JSON values in `dependency_graph_revision_history`.

The old graph, challenge snapshot, proposal, replay, review, and revision receipt remain preserved.

```text
LearningStructure != ErasingPriorStructure
```

Roles:


The bootstrap role initializes generation 0 only. Once a graph exists for a subject it cannot be silently replaced by a second bootstrap.

## Scope boundary

v1.14 governs a statistical dependency graph over model families. It does not retroactively rewrite historical `EvidenceDependencyDeclaration` receipts from v1.11 and does not fabricate concrete parent evidence hashes for past events.

Future evidence-instance dependency declarations remain exact provenance objects.

The graph is a structural statistical model that can guide future modeling/review; it is not a substitute for event-level provenance.

## Epistemic boundary

```text
DependencyCalibrationSignal != CausalityProof
GraphEdge != PhysicalCause
ReplayImprovement != CausalityProof
ReviewApproval != OntologicalTruth
StructuralMutation != HistoryErasure
```

v1.14 makes the observer's map of statistical dependencies revisable and auditable while keeping causal claims outside what the evidence contract can prove.
