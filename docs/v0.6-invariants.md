# ATMAN-LATTICE v0.6 — Additional Merge Invariants

These invariants extend the v0.4 core and the v0.5 replay/restore invariants.

## I-28 — Exact Common-Ancestor Proof

> Two branches may be reconciled as sibling futures only when both carry independently valid proof edges to the same exact source checkpoint.

Human-readable identity equality is insufficient.

```text
left_restore.source_receipt_hash == ancestor.receipt_hash
right_restore.source_receipt_hash == ancestor.receipt_hash
```

Both branch chains must also independently pass lineage validation.

## I-29 — Parent Future Non-Erasure

> A merge must not retroactively redefine either parent branch as if the merged result had always been its future.

The shape is:

```text
        left ----\
ancestor          +---- merged
        right ---/
```

not:

```text
ancestor -> merged
```

with the left and right histories silently discarded.

## I-30 — Conflict Resolution Completeness

> Every declared conflict must have exactly one explicit resolution before a merge can be admitted.

Let `C` be the set of conflicts and `R` the set of resolution records. Then:

```text
refs(C) == refs(R)
```

must hold exactly. Missing and extra resolutions are both invalid.

## I-31 — Resolution Integrity

> A resolution must bind to the exact competing values it claims to reconcile, and the resulting decision must be tamper-evident.

For each conflict:

```text
resolution.left_digest  == conflict.left_digest
resolution.right_digest == conflict.right_digest
```

`LEFT` must select the left digest, `RIGHT` must select the right digest, and `SYNTHESIZED` must explicitly commit to its result digest and reason reference.

The canonical resolution set is committed as `resolution_digest`.

## I-32 — Merge Lineage Fork

> Reconciliation creates a new executable lineage rather than reusing either parent lineage.

A valid merge requires:

```text
target_branch != left_branch
target_branch != right_branch
target_generation > max(left_generation, right_generation)
target_root != left_root
target_root != right_root
```

The target therefore represents a new history descended from both parents, not a disguised continuation of one parent.

## I-33 — Dual-Parent Provenance Binding

> A merged genesis must commit to both parent heads, the exact common ancestor, the conflict-resolution digest, and the merged payload digest.

The target genesis preserves explicit provenance references:

```text
merge-ancestor:<ancestor_receipt_hash>
merge-left:<left_head_receipt_hash>
merge-right:<right_head_receipt_hash>
merge-resolutions:<resolution_digest>
```

Substituting a different parent, target, or resolution set must make verification fail.

## v0.6 acceptance additions

A merge is provisionally admissible only when:

```text
common_ancestor_binding     = exact
left_restore_proof          = valid
right_restore_proof         = valid
left_branch_chain           = valid
right_branch_chain          = valid
parents_are_distinct        = true
conflict_set                = fully_resolved
resolution_digest           = valid
target_branch_is_new        = true
target_generation_advanced  = true
target_lineage_root_is_new  = true
dual_parent_provenance      = present
merge_receipt_integrity     = valid
```

The principal v0.6 counterexample is:

```text
left future  = valid
right future = valid
same ancestor = true
unresolved conflict = true

=> MERGE REJECTED
```

because valid histories do not become globally coherent merely by sharing ancestry.
