# ATMAN-LATTICE v1.11 — Multi-Hypothesis / Correlated Evidence Geometry

v1.11 extends the v1.10 Bayesian evidence loop in two directions:

1. a knowledge state can contain multiple competing hypotheses rather than only `H / not-H`;
2. evidence dependence becomes an explicit runtime contract so repeated/derived/conditional signals cannot be naively multiplied as independent evidence.

Protocol:

```text
ATMAN-MULTI/1.11
```

Worker:

```bash
python -m model.multi_worker
```

## Why

A binary posterior is insufficient when an agent is choosing between several plausible causal explanations:

```text
H:A  service regression
H:B  stale projection
H:C  authority/policy drift
```

And a second observation is not automatically a second independent evidence unit. For example:

```text
source event S
  |\
  | summary by agent A
  | summary by agent B
  | copied alert
  | derived dashboard metric
```

Several representations can originate from the same underlying event.

```text
DifferentMessages != IndependentEvidence
```

## Hypothesis distribution

`HypothesisDistribution` binds:

```text
distribution_ref
subject_identity_ref
[(hypothesis_ref, probability_bps), ...]
evidence_state_hash
generation
distribution_hash
```

The probability vector is canonical and normalized:

```text
sum probabilities = 10000 bps
```

Evidence redistributes mass across the whole declared set rather than silently deleting alternatives.

## Multi-hypothesis likelihood

`MultiLikelihoodModel` binds the exact distribution hash and provides:

```text
P(positive | H:A)
P(positive | H:B)
P(positive | H:C)
...
```

It may also bind an exact set of parent evidence hashes when the model is conditional on already-observed evidence.

For a positive observation:

```text
Posterior(H_i) proportional to Prior(H_i) * P(+ | H_i)
```

For a negative observation:

```text
Posterior(H_i) proportional to Prior(H_i) * (1 - P(+ | H_i))
```

Integer basis-point mass is normalized deterministically with largest-remainder allocation so the posterior sums exactly to 10,000 bps.

## Multi-hypothesis information gain

v1.11 also computes Shannon entropy over the full probability vector:

```text
H(P) = -sum_i P(H_i) log2 P(H_i)
```

and expected information gain for the binary test outcome:

```text
EIG = H(Prior) - E[H(Posterior | outcome)]
```

This remains model-conditional:

```text
ExpectedInformationGain != Truth
```

## Evidence dependency declaration

Before completion, `EVIDENCE_DEPENDENCY_KEEPER` declares one of:

```text
INDEPENDENT
CONDITIONAL
DUPLICATE
```

The declaration binds:

```text
candidate_hash
source_event_hash
derivation_hash
dependency_group_ref
mode
parent_evidence_hashes
declaration generation/time
```

### INDEPENDENT

No parent evidence is declared and the likelihood must be unconditional.

The runtime also refuses to accept a source event that has already been counted.

### CONDITIONAL

At least one accepted parent evidence receipt must be named.

The likelihood model must bind the exact same canonical parent evidence hash set:

```text
Dependency.parents == ConditionalLikelihood.parents
```

This prevents using an unconditional likelihood after observing correlated evidence.

### DUPLICATE

Exactly one accepted parent evidence receipt is named and the `source_event_hash` must be identical to the parent's source event.

A duplicate produces `DuplicateEvidenceReceipt` and is preserved in history, but does not advance the distribution.

```text
DuplicateEvidence != NewKnowledge
```

## Source event vs derivation

Two messages may have different derivation hashes while retaining the same source:

```text
source_event_hash = S

derivation_hash = D1  summary

derivation_hash = D2  translation

derivation_hash = D3  dashboard projection
```

v1.11 therefore makes this law load-bearing:

```text
DifferentDerivationHash != IndependentSource
```

## Process/database enforcement

Accepted evidence is persisted with a SQLite uniqueness constraint on `source_event_hash`.

Apply runs under `BEGIN IMMEDIATE`, so two processes racing to count the same source cannot both commit it as fresh accepted evidence inside the reference SQLite deployment boundary.

Duplicate representations use a separate duplicate-history table so they can be preserved without violating accepted-source uniqueness.

## Shared distribution and model freshness

Several candidates can bind one distribution.

When accepted non-duplicate evidence advances that distribution:

```text
Distribution N -> Distribution N+1
```

all cohort likelihood models still bound to Distribution N are mechanically freshness-rebased to N+1 while preserving their likelihood values and conditioning parent set.

```text
LikelihoodRebase != LikelihoodReEstimation
```

Evidence interpretation rules are not silently rewritten. If their bound model hash became stale, they must be explicitly refreshed before the candidate completes.

## Authority separation

v1.11 introduces distinct roles:

```text
MULTI_HYPOTHESIS_MODEL_KEEPER
EVIDENCE_DEPENDENCY_KEEPER
MULTI_EVIDENCE_RULE_KEEPER
MULTI_HYPOTHESIS_UPDATE_KEEPER
```

This prevents the same privilege from automatically defining:

- which explanations exist;
- whether evidence is independent;
- what PASS/HOLD/FAIL means as evidence;
- whether a posterior transition may commit.

```text
ModelAuthority != DependencyAuthority != InterpretationAuthority != UpdateAuthority
```

## Runtime operations

```text
register_distribution
register_multi_likelihood_model
register_evidence_dependency
register_multi_evidence_rule
preview_multi_update
apply_multi_update
get_multi_state
```

`preview_multi_update` returns either:

```text
UPDATE
```

with posterior/update/rebase receipts, or:

```text
DUPLICATE_NO_UPDATE
```

with a duplicate receipt.

Apply requires exact state/evidence/result hashes under current update authority.

## What this prevents

### Echo-chamber multiplication

```text
one event
-> five summaries
-> five Bayesian updates   X
```

### Unconditional multiplication of dependent observations

```text
Evidence B depends on A
but uses P(B | H) rather than P(B | H, A)   X
```

### Hindsight dependency classification

```text
observe result
-> decide whether it was independent   X
```

### Silent deletion of competing explanations

Posterior normalization preserves all declared hypotheses, including hypotheses driven close to zero.

## Security / epistemic boundary

The runtime can enforce exact dependency declarations and source provenance supplied to it. It cannot discover real-world statistical dependence from hashes alone.

A compromised or badly calibrated dependency/model keeper can still provide incorrect assumptions.

Therefore:

```text
ValidDependencyReceipt != ProvenRealWorldIndependence
ValidLikelihoodModel != EmpiricalCalibration
PosteriorDistribution != Truth
```

Production systems should derive source-event identity and dependency metadata from protected provenance/telemetry where possible and separately validate likelihood calibration.
